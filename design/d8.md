# D8: release and non-dependency automation

## Contract

### github-stats

1. Daily SVG generation MUST be restored, publishing to the generated branch with the existing `STATS_READ_TOKEN`. The generator job is privileged: it installs Zig inline with a checksum and clones with plain `git`.

### EasyHDR

2. On a published release, the release job MUST first check that the tag commit is reachable from main. A `windows-latest` job then builds and checks the `.exe`.
3. An `ubuntu-latest` shell-only job holding `VT_API_KEY` and `contents: write` MUST take the `.exe` in through intake steps 1–2 ([security.md](security.md#contract)), submit it to VirusTotal with `curl`, and attach it and the report links to the release.
4. The nightly dependency audit MUST be restored; cargo-geiger MUST NOT be.
5. Miri MUST run weekly and on dispatch, error-module tests only, outside the required checks.
6. Profiling MUST be manual dispatch only, with artifacts.
7. CI MUST cover the `fuzz/` crate.

### homebrew-taps updater

8. It MUST run every six hours, serialised, committing updates straight to main without PRs and without force-pushes, pushing with the repo's deploy key (rule 12, D16).
9. Job 1 (unprivileged, macOS) MUST fetch the app, compute the checksum, generate and validate the recipe, and output only the version and checksum.
10. Job 2 (privileged) MUST run the repo's own discovery script from main, require job 1's version to equal the latest and be newer than the cask's current one (`sort -V`), fetch the app itself, require the checksum to match, and publish the release from its own copy.
11. Job 3 (unprivileged) MUST run the checks that need the published download.
12. Job 4 (privileged) MUST rewrite only the cask's `version` and `sha256`, and push as a plain fast-forward over SSH with the deploy key: a mode-600 temp key, `IdentitiesOnly=yes`, and `known_hosts` built from GitHub's published host keys, never `StrictHostKeyChecking=no`.
13. Retries MUST finish whichever of the release or the recipe push is missing.
14. Linux formulae (D13): changed formulae MUST be built and tested natively on x86_64 and ARM64, feeding `ci-ok`.
15. PR #3 MUST be reconciled onto current main in a replacement PR (building on the merged #6), keeping the publication allowlist. The replacement PR opens an issue for the deferred bottle publication; #3 is closed as superseded only after both architectures pass.

### Other repos

16. poyo-studio (D13): a macOS job MUST run `test:media-tools:ci` with ExifTool, ImageMagick, FFmpeg and ffprobe installed, required in `ci-ok`. A missing tool MUST fail the job.
17. docrewind gets no release automation (deferred).

## Parameters

- homebrew-taps PR #30 is stale (it would downgrade paicord).

## Verification

- `VT_API_KEY` exists in EasyHDR (`gh secret list`).
- A tag not reachable from main fails the EasyHDR release job before any build.
- A homebrew-taps deploy-key push to main is accepted by the ruleset and starts `push` CI (settings-A1).
- homebrew-taps: a rerun after a failed recipe push publishes nothing twice and pushes the recipe.
- poyo-studio: removing one media tool fails the macOS job.

## Open

- None beyond settings-A1.

## Why

- Every job holding a secret or write credential runs only our own shell; builds needing actions run unprivileged ([security.md](security.md#why)).
- Job 2 re-derives version and checksum itself, so job 1's output is only a claim.
- A plain fast-forward push can't overwrite a concurrent change on main.
